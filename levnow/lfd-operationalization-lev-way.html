Architecture Boundary

How An Upstream LFD Artifact Becomes Lev-Native

flowchart LR
  A["LFD concept / artifact"] --> B["Lev owner-local eval-design source"]
  B --> C["FlowMind / orchestration topology"]
  C --> D["Poly or core-exec adapter boundary"]
  D --> E["core/eval observations and measurements"]
  E --> F["EvalDecision verdict"]
  F --> G["execution-ledger and XDG evidence refs"]
  H["score-cycle.py weighted score"] -. measurement only .-> E
  I["project logs and reports"] -. fixture/projection only .-> G
  F -. owns promotion .-> J["Proposal / exec readiness"]

External score output is an input measurement. It never becomes the final Lev verdict.

Execution Path

Operationalization Next Steps

Step 1

Feature map lock

Add a parser that reads `bundle.json`, verifies all skill/adapter/script targets, and records the locked inventory in the spike manifest.

Step 2

Fake verifier adapter

Read `verification-report.json` and emit command observations, diagnostics, evidence refs, and non-authority score projections.

Step 3

Proposal-readiness absorption

Require target, constraints, instruments, forced entropy, and harness completeness in proposal-readiness fixtures if the spike proves fit.

Step 4

Adapter contract spike

Convert the fake-agent wrapper contract into a typed Poly/core-exec adapter fixture and shared `AgentCycleSummary` output.

Step 5

Instrument taxonomy mapping

Create measurement lane mapping for every verified script and statically assert lane, authority, and owner coverage.

Step 6

FlowMind loop projection

Model cycle/run-loop behavior as bounded orchestration only after fake-verifier mapping is green.

Step 7

Live-agent gate

Run real adapter gates only when provider binaries are present; unavailable providers become explicit matrix rows, not base failures.
