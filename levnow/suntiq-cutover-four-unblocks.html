01 · Telemetry

One safe data plane; two possible control planes

The existing backend stays authoritative while the new Suntiq backend receives a mirror. The choice is how operators apply that configuration.

Implemented branch

Full manifest state machine

Named phases track prepared, mirroring, committed, observing, rollback, and finalization. Both services acknowledge a shared manifest and the operator records receipts. It is safe, but exposes more states and recovery paths than this cutover currently needs.

Recommended: small transactional operator

Use one named-target configuration. Write it to a temporary file, atomically replace the active file, reload both services, and require matching acknowledgements. If either service fails, restore the prior file. The operator succeeds completely or returns the system to the last known configuration.

02 · Production rehearsal

Approval is scoped to the new disconnected stack

Production-labelled resources still require explicit permission even before live traffic reaches them.

The bounded rehearsal

  1. Export a recoverable pilot Convex snapshot.
  2. Deploy the staging-accepted schema and functions to the new production Convex deployment.
  3. Import the full-fidelity pilot snapshot.
  4. Reconcile users in App Production Clerk against an exact identity manifest.
  5. Validate app.suntiq.ai login, tenant membership, boats, trips, and telemetry.

The approval can cover this bundle in one sentence. It is required because deploying backend code, importing production data, and changing production identities are real mutations even while the stack remains disconnected.

What remains untouched

No live DTU routing, device configuration, pilot DNS, fleet.argomarine.ai, billing, webhooks, or outbound provider effects. The rehearsal copy is replaceable; the final cutover can refresh it from a newer snapshot.
