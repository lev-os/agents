03 · Target architecture

Leaf freshness flows into one audited semantic boundary

Branch triggers, provider graphs, semantic cards, and business queries keep separate owners.

flowchart TD
  Merge["Merge to manifest baseline branch"] --> Leaf["Leaf graph rebuild"]
  Leaf --> Receipt["Graph generation and commit receipt"]
  Receipt --> Ingest["Context Engine delta ingest"]
  Entities["Repo-generated .ulta/entities"] --> Normalize["Canonical normalizer"]
  Ingest --> Normalize
  Cross["Native CBM CROSS_* evidence"] --> Normalize
  Normalize --> Audit["Semantic audit<br/>identity, evidence, freshness, conflicts"]
  Audit --> Candidate["Candidate evidence boundary"]
  Candidate --> Promote{"Validation passes?"}
  Promote -->|"yes"| Active["Active semantic read model"]
  Promote -->|"no"| Gaps["Explicit gaps and stale claims"]
  Query["Business query"] --> Scope["Scope resolver"]
  Scope --> Retrieve["Evidence retriever"]
  Retrieve --> Active
  Active --> Response["Typed chains, raw refs, confidence, gaps"]
  Gaps --> Response

The baseline branch comes from the repo manifest, so iPhone and Android can remain on master while most repositories use develop.

Four responsibilities, one query contract

Source repository CI owns one leaf rebuild for the branch declared in repo-manifest.yaml. It publishes a generation and evidence receipt; it does not build a company graph.

Codebase Memory and other providers own structural extraction. Their cross-project edges are raw evidence, never canonical business truth.

Context Engine owns normalization, semantic identity, evidence admission, freshness, conflicts, candidate boundaries, promotion, and the shared graph.query / graph.explain response contract.

The agent or skill owns query decomposition during the POC: ScopeResolver → EvidenceRetriever → SemanticJoiner → ChainAuditor. Those routines consume manifest and ontology data; they do not memorize the org chart in prompt prose.

04 · Options

Three routes, one that survives production scrutiny

The comparison separates POC speed from long-term authority.

Why the hybrid wins

It preserves the cheapest useful behavior from both alternatives. Native provider edges stay available when the source extractor can prove them. Agent reasoning accelerates discovery, but every inferred hop remains candidate evidence. Context Engine supplies the missing durable contract: typed identity, audit, freshness, conflicts, confidence, and a business-facing query response.

05 · Proof plan

Prove the joins before building the service

The POC is intentionally bounded to three repos and one business path.

01

Semantic baseline

Run the agent/skill against web-site, exp-graphql, and orch-buy without graph mutation. Resolve scope from the manifest, retrieve raw graph hits, join typed .ulta/entities, and return admitted paths, candidates, and gaps.

02

Native matcher

Run CBM cross-repo intelligence in isolated graph stores. Capture the number and shape of CROSS_* edges, plus every miss caused by unresolved constants, dynamic paths, or missing handler identity.

Decision receipt

Compare business-question accuracy, evidence-ref coverage, wrong admitted edge rate, regeneration time, and manual edge count. Promote to proposal only if the hybrid materially improves answer quality without hiding candidate joins.
