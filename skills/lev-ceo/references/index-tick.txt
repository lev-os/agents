Steps
1. Run `date -u +%Y%m%dT%H%MZ`. That is STAMP. Make the folder S/pass-STAMP.
2. List the chats with a program, not with a T3 tool:
   `node K/list-chats.mjs --projects S/projects-20261118T2035Z.json --out S/threads-STAMP.json`
   It uses the t3 command line and prints the count. When it exits 1, stop: reply "tick skipped:" and its last
   line. Never read the list into your context; use jq for a count.
3. Scan: `node K/sweep.mjs scan --threads S/threads-STAMP.json --projects S/projects-20261118T2035Z.json --self OWNER --text`
   Keep its first line (the counts).
4. Count the chats to read: `grep -c "" S/to-read.jsonl` (0 when the file is empty or missing). When it is 0, load
   no T3 tool and read no chat: go to step 5. When it is over 0, load the read tool with ToolSearch, query
   `select:mcp__t3-code__t3_thread_read`, then:
   `node K/sweep.mjs brief --out S/pass-STAMP/labels.jsonl > S/pass-STAMP/label-brief.txt`
   Read S/pass-STAMP/label-brief.txt in full and do what it says yourself: it is the order for the label reader, and
   you are that reader. Then `node K/sweep.mjs merge --labels S/pass-STAMP/labels.jsonl`.
5. Queue: `node K/sweep.mjs queue --thread OWNER --title "CEO > global"`
6. Cards: `node K/cards.mjs brief --thread OWNER --out S/pass-STAMP/cards.jsonl > S/pass-STAMP/card-brief.txt`
   When the brief names at least one chat, read it in full and do what it says yourself: you are the card reader.
   Write each card for a reader who has never seen the chat: plain words, no code name, no file name, no id without
   its meaning in the same sentence. Then `node K/cards.mjs merge --thread OWNER --cards S/pass-STAMP/cards.jsonl`.
7. Check each open item. You are the CEO chat's agent (JP 2026-11-20: "u have the automation chat u made, thats ur
   fucking agent, it should be doing anything agentic"), so JP gets no card that is stale or that an agent can do.
   a. `node K/queue.mjs show --thread OWNER | jq -r '.items[] | select(.status == "pending" or .status == "presented") | .threadId' > S/pass-STAMP/open-ids.txt`
   b. `xargs node K/chat-tail.mjs --max 2500 < S/pass-STAMP/open-ids.txt > S/pass-STAMP/tails.jsonl`
      It reads through the t3 command line. Exit 1 means one chat could not be read: its line holds `error`; go on.
   c. Read S/pass-STAMP/tails.jsonl, and S/checks.json when it exists. A chat whose `updated_at` is the one in
      S/checks.json keeps its old entry. For each other chat, list each question that the end of its last reply
      puts to JP, and answer two things for each:
      - still_asked: false when the chat runs now, when a person wrote after the reply, when the reply holds no
        question for JP, when JP paused or parked the chat (his last message says pause, later or not now), or when
        the reply itself says that nothing needs an answer now. True in every other case.
        A question that rests on the state of another chat ("that chat waits on a request", "that chat holds the
        simulator") is checked before it is judged: run `node K/chat-tail.mjs --max 600 <that chat's id>` (add
        `--ssh kingly-macbook` for a chat on the MacBook). When the other chat does not show that state, the
        question is stale: still_asked false, and `why` says what the other chat shows.
      - agent_can: true when an agent can do what the question asks. That is: a page of a service that JP is signed
        in to in Brave on this Mac, a setting that a program can read, an app that an agent can start, a test or a
        click that an agent can do, a routine commit or push, and a question that a plan, a rule or a ruling of JP
        already answers. False only for: production, money, a message to a person, a new sign-in on his machine,
        product taste, public text under his name, and a delete that cannot be undone. A question whose
        recommended choice keeps a name, a flag or a state as it is mints nothing: an agent can do it. Give the
        reason in `why`, in plain words, one sentence.
   d. Write S/checks.json with the Write tool, one JSON object:
      {"at": "<UTC now>", "chats": [{"thread_id": "...", "title": "...", "updated_at": "<from the tail line>",
       "checked_at": "<UTC now>", "questions": [{"ask": "<the question in plain words>", "still_asked": true,
       "agent_can": false, "why": "..."}]}]}
      You judge only. You send nothing and you do none of the errands: the chat that asked does them.
   e. Give each chat of S/checks.json its band (JP 2026-11-20: "Foundation and mvp are really the focus"; the three
      bands are in K/../references/goal-map.md, The sequence). Take the band from the project's records, never from

        chat's title words there); give the step id.
      - mvp: its work is an item of .lev/pm/roadmap/backlog.yaml with `mvp: true` (grep the item by the words of the
        chat's topic); give the item id.
      - future: the item has `mvp: false`; give the item id.
      - cannot tell: no step and no item found; say what you searched.
      Add to the chat's entry: "band": "<foundation|mvp|future|cannot tell>", "band_record": "<step or item id, or
      the search>". A chat of another project gets "cannot tell" with "band_record": "another project".
      Never load backlog.yaml whole: it is large. Use grep -n with a few lines of context.
