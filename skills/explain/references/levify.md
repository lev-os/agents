# Explain: Lev context router

Use this leaf for explicit `--levify` or when a selected explanation benefits
from the bound project's Lev idioms. It adds context to Explain, not another
runtime, skill, public kind, CLI command, or authority.

1. Bind the target project using [Project Context](../../lev/references/project-context.md).
   Read its applicable `AGENTS.md`, effective config breadcrumbs and relevant
   local owner skills. Keep the explained project separate from the Lev installation.
2. Follow its configured Lev IR router and vocabulary; in Leviathan these are
   `dna/index.yaml` and `dna/vernacular.yaml`. Reach `dna/graph.yaml` for primitive,
   depth and lifecycle definitions, then only the relevant owner contracts.
   Verify current source/receipts where declarations or historical paths drift.
3. Load the existing [Lev skill](../../lev/SKILL.md). Classify intent as that
   project's conversational router would: understand, diagnose, shape, decide,
   or act. Explain why a lifecycle route applies; dispatch follows the user's
   actual authorization and the route's existing prerequisites.
   During explanation, use its routes as lookup guidance and report the next
   eligible route. Explain's read-only scope takes precedence over delegated
   automatic-Next/controller bookkeeping: run no controller hooks or lifecycle
   writes unless a separate user request authorizes those actions.
4. Disambiguate, look for conflating/overloaded terms, and do domain modeling.
   Map each material user concept to its existing term, facet, owner and layer;
   consolidate aliases only when their meanings and sources agree. `unmapped`
   is a finding to explain or clarify, never a prompt to mint canon.

## Lev development context

When the subject is Lev itself, also consult its relevant local gate skill
(`lev-canon`, core boundaries, plugin/runtime build, proof, or split-brain audit)
and the owning spec/Lev IR pair. Preserve the independent meanings of ontology,
Lev IR facets, representation, module responsibility, lifecycle stage, alignment,
and runtime status. A compiled flow graph and a context graph are different
representations. An approved specification does not establish a completed run.
Read entity state where recorded; leave missing stage/alignment unverified.

Show deterministic-code versus Lev IR changes when relevant, what code and LLMs
handle, and product versus dogfood. The existing lifecycle skills own capture,
interview, planning, proposal, execution, verification and handoff. This leaf
routes to them instead of copying their protocols or advancing entity state.
