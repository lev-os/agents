# T3 Code threads through the `t3` command line

Use `t3 thread` to read, message and start T3 Code threads (JP's word: chats)
from a session outside T3: Claude Code, Codex, a terminal. A session inside T3
has the `t3-code` MCP tools and uses those.

Observed on T3 Code (Beta) 0.1.7, 2026-11-09. Live help is the source of truth:
`t3 <command> -h`. The long form after a subcommand (`t3 thread list --help`)
fails with "Unknown command"; use `-h`.

## Connect

```bash
T3="$HOME/.t3/bin/t3"     # a wrapper that runs the desktop app's bundled CLI
"$T3" --version
"$T3" thread list --project . --json | jq length
```

The wrapper needs the desktop app installed and its server running (open the
app once). `--project` takes a project id or a path inside the project; it
defaults to the current directory. Exit 1 with "No T3 Code project matches"
means the path is outside every T3 project.

## Read

```bash
"$T3" thread list --project . --json      # newest first, one object per thread
"$T3" thread show "$THREAD" --messages 5 --json
```

- A thread id has three forms: `<uuid>`, `mcp:<uuid>` and `mcp:launch:<hash>`.
  Quote it. Take it from `thread list`, never from a title.
- `list` rows carry `threadId`, `title`, `status` (`idle`, `completed`,
  `failed`, `interrupted`, plus a running state), `settled`, `snoozed`,
  `parentThreadId`, `model`, `updatedAt` and `link`.
- `show` returns `{thread, messages}`. `thread` adds `activeRunId`,
  `pendingRequestCount`, `archived`, `branch` and `worktreePath`; each message
  is `{role, runId, text}`.
- A thread waits for a person when `pendingRequestCount` is above 0. A thread
  works when `activeRunId` is set.
- `link` is the page to give a person. The in-app form is
  `t3-thread://v2/<environment id>/<thread id>`.

## Send and start

Both are outward acts: the agent in that thread acts on the text. Send only text
the user approved for that thread. Read the thread first (`show`), so the
message answers its real last state.

```bash
printf '%s' "$MESSAGE" | "$T3" thread send "$THREAD" - --json
"$T3" thread send "$THREAD" "$MESSAGE" --wait        # prints the reply
"$T3" thread start . "$MESSAGE" --title "area > topic" --json
```

- `-` reads the message from stdin; use it for anything longer than one line.
- A busy thread takes the message as its next turn. Nothing is interrupted.
- `--wait` blocks until the run ends: exit 0 with the reply, exit 1 when the run
  failed, exit 2 when the thread waits for an answer. A run can take many
  minutes, so run a `--wait` call in the background.
- `start` flags: `--title`, `--provider` with `--model`, `--worktree <base>`
  with `--branch <name>`. It prints the new thread id.
- A send that timed out has an uncertain effect. Run `thread show` and look for
  the message before you send again.

Done: `thread show` lists the message with `role` user, and a later run id
follows it.

## What the command line does not do

| Need | Route |
|---|---|
| Rename, settle, snooze or archive a thread | The T3 app, or a session inside T3 |
| Read what a pending request asks | `thread show` gives the count only; open `link` |
| Scheduled tasks, child threads, the thread queue | The `t3-code` MCP tools inside T3 |
| History older than `--messages` returns, or a query across projects | Read `~/.t3/userdata/statev2.sqlite` with `sqlite3 -readonly` (tables `orchestration_v2_projection_threads`, `_messages`, `_runs`); never write to it |

## MCP and tokens

T3 serves MCP at `http://127.0.0.1:<port>/mcp` (3773 by default). It makes the
bearer token for each provider session inside T3, tied to one parent thread, so
an outside session has none. `t3 auth session issue` mints a bearer token for an
outside client; whether `/mcp` accepts that token is not tested. Minting a token
is the user's act: ask first, and keep the value out of chat, files and logs.

Other subcommands (`project`, `app`, `status`, `doctor`, `trace`, `service`,
`update`, `uninstall`) change or inspect the installation. Read `-h` first;
`doctor` repairs the data directory and restarts the service, and `uninstall`
removes `t3`.
